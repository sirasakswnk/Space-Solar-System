## สภาพแวดล้อมที่ใช้ตรวจจริง

- เครื่อง: คอนเทนเนอร์ Linux บนคลาวด์, CPU 4 คอร์, RAM 15 GB, ไม่มี GPU
- เบราว์เซอร์: Chromium 141.0.7390.37 แบบ headless ผ่าน Playwright, WebGL ผ่าน SwiftShader (เรนเดอร์ด้วย CPU)
- Node.js v22.22.0 / npm 10.9.4; ตรวจทั้ง dev server (Vite) และ production build (`vite preview`)
- ขนาดหน้าต่าง: 1280×720, 1440×900, 1920×1080
- ไม่ได้ตรวจบน Windows, Chrome/Edge ที่ติดตั้งจริง หรือการ์ดจอจริง (งาน S00–S09k เคยตรวจบน Windows/Headless Chrome)

## สิ่งที่แก้ระหว่างตรวจ

- พบใน #13: หลังออกจากโหมดสำรวจมีช่วงพัก 180ms ที่ไม่รับค่า scroll; ถ้า scroll เกิดในช่วงนั้นแบบทันที (ลาก scrollbar หรือสั่งด้วยโปรแกรม) ยานจะไม่ตามจนกว่าจะเลื่อนครั้งถัดไป
- แก้ `src/journey/useJourneyScroll.ts`: เมื่อช่วงพักจบให้อ่านตำแหน่ง scroll อีกครั้ง; ล้อเมาส์ในช่วงนั้นยังถูกกันเหมือนเดิม
- ยืนยัน: scroll ทันทีหลังออก → progress ตามถึง 1; ล้อเมาส์ระหว่างกำลังออกถูกกัน ไม่ขยับ (cooldown-results)

## ข้อสังเกตจากการตรวจ (ไม่ใช่ข้อบกพร่องของเว็บ)

- สคริปต์ตรวจหลายครั้งให้ผลผิดเพราะตัวสคริปต์เอง แล้วแก้สคริปต์: ไม่คิดการเบนตามเมาส์ (S09m), รอการขยับกล้องไป hotspot ไม่พอบนเครื่องช้า, วัดกรอบ `<p>` ที่กว้างเต็มแถว
- สคริปต์ S09l (`behave`) เทียบมุมกล้องหลังคลิกด้วยเมาส์ จึงไม่ผ่านหลังมี S09m; เปิดด้วยคีย์บอร์ดแล้วผ่าน (`behave-keyboard.mjs`)
- ข้อความจุดข้อมูลบางข้อพูดถึงการกดในฉาก 3D (เช่น Saturn) ซึ่งไม่มีในหน้าสำรอง WebGL

## สิ่งที่ยังไม่ได้ทดสอบหรือทดสอบได้ไม่ครบ

- ประสิทธิภาพ: ไม่ได้วัด FPS บนเครื่องอ้างอิงตามที่ผู้ใช้สั่งข้าม; มีเพียงแนวโน้มบน SwiftShader (เบา 21.7 / มาตรฐาน 16.8 fps ใน S10b) ซึ่งไม่ใช่ผลบนการ์ดจอจริง
- Bundle 1,331 kB (gzip 377 kB) ยังไม่แบ่งไฟล์; คำนวณตำแหน่งปุ่มจุดข้อมูลทุกเฟรมทั้ง 7 ดวงยังไม่ปรับ
- Windows + Chrome/Edge จริง และการ์ดจอจริง: ไม่ได้ตรวจรอบนี้
- ฟอนต์ไทย: เครื่องนี้ไม่มี Leelawadee UI/Tahoma จึงแสดงด้วยฟอนต์สำรองของระบบ; ฟอนต์จริงบน Windows ยังไม่ได้ตรวจด้วยภาพในรอบนี้
- ลดการเคลื่อนไหวตรวจด้วยการจำลองค่าระบบ (emulateMedia) ไม่ใช่สวิตช์ของระบบปฏิบัติการจริง
- ไม่มี WebGL ตรวจด้วยการจำลอง (override getContext) ไม่ใช่เบราว์เซอร์ที่ปิด WebGL จริง
- ล้อเมาส์ในช่วงพัก 180ms หลังออกสำรวจ: จับเวลาให้ตรงช่วงด้วยสคริปต์ไม่ได้แน่นอน (โค้ดส่วนนี้ไม่ได้เปลี่ยน)
